# Advocates.jp デザイン検討資料

作成日: 2026年10月14日

[コンテンツ検討資料](./content-plan.md)で決めた内容をもとに、デザインの方向性を検討した記録です。taste-skill（design-taste-frontend）の手順で方向性を決め、トップページと、フッターから開く2ページの試作を作りました。試作は `site/` にあります。

## 1. 試作の見方

| ファイル | 内容 |
| --- | --- |
| `site/index.html` | トップページ |
| `site/company.html` | 会社概要（フッターのリンクから開く） |
| `site/ad-policy.html` | 広告表示に関する方針（フッターと本文のリンクから開く） |
| `site/styles.css`、`site/main.js` | 3ページで共通のスタイルと動き |
| `site/assets/` | 写真6枚と、その出典（`credits.json`） |

`site/index.html` をブラウザで開けば表示されます。サーバーは要りません。フォントは Google Fonts と Fontshare から読み込むため、表示にはネットワーク接続が必要です。

## 2. 先行事例から分かったこと

8社のトップページを、taste-skill の検査スクリプトでブラウザに表示して計測しました（2026年10月14日）。

| 会社 | 最初の画面 | 計測した書体と本文の大きさ | 参考にした点 |
| --- | --- | --- | --- |
| アミューズ | 理念「感動だけが、人の心を撃ち抜ける。」を大きな文字だけで見せる | 小塚ゴシック、本文14px | 理念を最初の画面に置く。読者別の入口（個人／法人／アーティスト募集）。なりすましスカウトへの注意 |
| LDH JAPAN | 所属アーティストの画像を切り替えて見せる | Roboto、本文13px | 専門家のカテゴリ（CULINARY ARTIST、SPECIALIST） |
| ホリプロ | 公演の広告画像を大きく見せる | メイリオ、本文14px | なし（ファン向けの構成） |
| スターダストプロモーション | 所属タレントの検索とニュース | 游ゴシック、本文16px | なし（ファン向けの構成） |
| Whalar | 写真の上に主張を大きな英字で置く | Founders Grotesk、本文21px | 主張を言い切る見出し |
| Digital Brand Architects | 社名の文字の形の中に、所属クリエイターの写真を入れる | Mont Blanc、本文12px | 名前と人の写真を一体にする考え方 |
| キャスティングドクター | 電話番号と写真の切り替え | メイリオ、本文15px | なし |
| シンサツマエ | 動画の上に「医療者の発信が、社会を変える。」 | Noto Sans JP、本文16px | 理念を一文で言い切る |

分かったことは次の3点です。

- 大手の芸能事務所は、所属タレントの写真や公演の告知を最初の画面に並べている。所属タレントの一覧を載せない Advocates は、アミューズのように考え方を最初の画面に置く形が合う。
- 専門家を扱う事務所（シンサツマエ、キャスティングドクター）は、明るい青の配色、人物の素材写真、アイコンを付けたカードを使っている。この見た目を避ければ、同じ分野の会社と区別しやすい。
- 日本の6社のうち4社は本文が13〜15pxで、5社は文字の大きさが10種類以上あった。試作では本文を19px（スマートフォンでは17px）にし、大きさを5種類に絞った。

## 3. 方向性

taste-skill のスクリプトが示した3つの方向性から、「The sentence is the layout（一文がそのままレイアウトになる）」を選びました（seed 1688524401）。大きく置いた一文の中に、単語の代わりに写真の枠を入れる方向性です。

| 方向性 | 内容 | 判断 |
| --- | --- | --- |
| Colour chapters | 章ごとに画面いっぱいの色面を変える | 不採用。Advocates に固有の要素と結びつけにくい |
| Type and nothing else | 最初の画面を文字だけで作る | 不採用。アミューズと同じ見え方になる |
| The sentence is the layout | 一文の中に写真の枠を入れる | 採用 |

選んだ理由: Advocates の言葉には、もともと空欄があります（「〇〇×インフルエンス」の〇〇）。考え方の「Who」も、誰が薦めるかという空欄です。一文の中に写真の枠を置く方向性なら、その空欄を写真で見せられます。

| 項目 | 内容 |
| --- | --- |
| 配色 | 白い紙と黒いインク。「相談する」のボタンは、白い章では黒、黒い章では白に反転させる（2026年10月14日、明るい青から変更）。差し色は赤（#d7261e）1色で、考え方の言葉「Who」と「誰が」（最初の画面と、考え方の見出しと本文）、キーボード操作時の枠、文字選択の色に使う（2026年10月14日、ボールペンの青 #1a4be0 から変更）。白い面との比は 5.0:1。章ごとに白、薄い灰色（#f4f4f4）、黒の面を切り替える |
| 書体 | 英字の見出しは Zodiak（細いセリフ体）。日本語と本文は Zen Kaku Gothic New |
| 文字の大きさ | 5種類（14、19、33、65、135px。1440px幅のとき） |
| 最初の画面の見出し | 横長の画面では「Who ▢ Advocates」と「Matters」の2行。縦長の画面では「Who ▢」「Advocates」「Matters」の3行にし、Advocates が画面の幅いっぱいになる大きさにする。写真の枠の右端は Advocates の右端にそろえる（2026年10月14日） |
| 角 | 写真もボタンも角丸にしない |
| 動き | 下にある章の色に合わせてヘッダーの色が変わる。各章の要素は、画面に入ったときに一度だけ下から現れる。スクロールを始めると、右下に「ページの先頭へ」のボタンが出る |
| メニュー | 幅が960px以下の画面では、メニューを三本線のアイコンにまとめる。開くと×に変わる |

taste-skill の指定から変えたところは次のとおりです。

- 指定の本文書体 Hanken Grotesk は日本語を表示できないため、Zen Kaku Gothic New に替えた。書体は2種類のままです。
- 指定の構成ではお問い合わせとフッターの両方でメールアドレスを大きく見せることになり、重複する。そのため、お問い合わせの章をなくし、フッターをメールアドレスで締める形にまとめた。会社概要へのリンクもフッターに置いた。フッターの上の大きな余白はなくした。
- 指定の構成の「実績の社名を一文に並べる」章は、実績がないため、広告表示の方針を一文に並べる形に置き換えた。

## 4. アイデア

> このページでは、「専門性×インフルエンス」の専門性、つまり「誰が」の部分が、一文の中の写真の枠になる。

- 最初の画面の「Who ▢ Advocates Matters」の枠に、日本語キーボード、電卓アプリを開いたスマートフォン、裁判所の看板、マーカーペン、鉛筆で字を書く子どもの手元、昭和の台所の写真が順に入れ替わる。
- 専門性×インフルエンスの章では、閲覧者が専門分野（弁護士、税理士、エンジニア、デザイナー、主婦、教育者）を選ぶと、写真と「例：会計ソフトやお金のサービスを、数字を扱う専門家の目で紹介できます。」のような説明が切り替わる。これがページの中で閲覧者が操作できる部分です。JavaScript が動かない環境では、6つの例を一覧で表示します。

## 5. トップページの構成

ヘッダーのメニューは「考え方」「企業の方へ」「お知らせ」と「相談する」のボタンです。

| 順 | 章 | 見せ方 | 主な文 |
| --- | --- | --- | --- |
| 1 | 最初の画面 | 白と黒の2つの面の境目に、英字の一文を置く | Who ▢ Advocates Matters ／ 専門性と発信力をあわせ持つ人の、マネジメント会社です。 |
| 2 | 考え方 | 左の見出しを画面に固定し、右側を3つの理由と写真が流れる | 誰が薦めるかで、伝わり方は変わる。（AI で知識が誰にでも手に入るようになったことと結びつけた3段の説明） |
| 3 | 専門性×インフルエンス | 段落の頭に写真を置き、左の専門分野を選ぶと切り替わる | 弁護士 × インフルエンス。Advocates が仕事をするのは、資格や実務経験で確かめられる専門性と、それを届ける発信力を、両方持つ人です。 |
| 4 | 企業の方へ | 画面の35%の位置から、施策の名前と説明を2列で並べる。写真は使わない | 専門家の言葉で、商品を伝える。（PR 投稿、アンバサダー、監修、出演、共同開発） |
| 5 | 広告表示の方針 | 黒い面に方針を一文で並べ、1項目ずつ順に白く表示する | 広告であることを隠さない、「#PR」などの表記を入れる、投稿の前と後に確かめる、信用を損なう案件は受けない。 |
| 6 | お知らせ | 見出しの下に、画面の35%の位置から一覧を置く。題名を押すと本文が開く | サイトの公開、方針の公開、Advocates を名乗る連絡についての注意 |
| 7 | フッター | 黒い面に「お問い合わせはこちらから」とメールアドレスを大きく置き、その下に小さな文字でリンクを並べる。どちらの文を押してもメールが開く | お問い合わせはこちらから、Contact@advocates.jp、会社概要、広告表示に関する方針、プライバシーポリシー（準備中）、© 2026 MYK.LLC |

所属について（4つの文を階段状に並べた章）と、フッターの運営・受付・返信の目安の文は、2026年10月14日に外しました。同じ日に、企業の方への章の写真と、お知らせの横に置いていたスカウトについての注意書きも外しました。注意書きは、お知らせ「Advocates を名乗る連絡について」の本文に移しています。

メールアドレスのリンクは、件名と、お問い合わせフォームの項目（相談の種類、名前、会社名、活動名と SNS、内容）を記入済みのメールを開きます。フォームの送信の仕組みは、技術スタックを決めるときに選びます。

## 7. 検査の結果

taste-skill の検査スクリプト（`lint.mjs` と `inspect.mjs`）で、1440、768、390px の幅を確認しました。

- トップページは、禁止している表現（グラデーション、影、小さなラベル、番号付けなど）と、本文の大きさ、文字と背景のコントラスト、横へのはみ出しの検査を通過しました。広告表示の方針の章で薄く表示する文字は、スマートフォンの文字の大きさでもコントラスト比4.5:1を満たす色（#808080）にしています。
- 縦長の画面（768px と 390px）では、最初の画面の見出しが3行になるため、「見出しは2行まで」の検査に通りません。ご指定により3つの語を1行に1語ずつ積んだもので、この検査が防ぐ「文を折り返した見出し」とは違うため、このままにしています。
- 警告が2件残っています。1件は動画がないことです。写真の雰囲気に合う25MB以下の映像が見つからなかったため、最初の画面の写真をゆっくり拡大する動きで代えています。もう1件は、考え方の見出しが3画面のあいだ固定されることです。3画面それぞれに別の理由と写真が入るため、このままにしています。
- 会社概要と広告表示の方針のページは、写真と動きの最低数の検査に通りません。文書のページなので、写真や動きは加えていません。
- 画面写真を見ての評価は、2回目で7.9点（10点満点。デザイン8、使いやすさ8、独自性8、内容7）でした。1回目で指摘した3点（専門性の章の内容が薄い、広告表示の方針の上の余白が大きい、スマートフォンの見出しが小さい）を直しています。この評価は、写真を替える前の画面でのものです。
- ブラウザで次の動作を確かめました（写真を替えたあとの画面）。写真の枠の切り替え、専門分野の選択、章に合わせたヘッダーとボタンの色の切り替え、スマートフォン幅での三本線のメニュー、スクロールを始めたときの「ページの先頭へ」の表示と、押したときに先頭へ戻ること。縦長の画面（390×844、768×1024、1000×1000）で見出しが3行になり、写真の枠の右端が Advocates の右端にそろうこと。横長の画面（1440×900、844×390）では2行のままであること。お知らせの題名を押すと本文が開き、キーボード（Enter キーとスペースキー）でも開閉できること。フッターの「お問い合わせはこちらから」とメールアドレスが一つのリンクとして読み上げられること。

## 8. 公開前に確かめる内容

次の内容は、デザインを確かめるために仮に入れたものです。

- 企業の方へに並べた施策（PR 投稿、アンバサダー、監修、出演、共同開発）。コンテンツ検討資料の 5.2 の4で決めます。
- 専門分野の例に挙げた6つの分野の説明文。
- お知らせの日付（2026.11.04）と、3件の題名と本文。
- お知らせ「Advocates を名乗る連絡について」の本文（スカウトや連絡は @advocates.jp のメールアドレスから行うという案内）。実際の連絡方法に合わせます。
- 会社概要の「（仮）」の項目。
- 広告表示に関する方針の文面。公開前に、弁護士などの専門家に確認することを勧めます。
- プライバシーポリシー（未作成）。

## 9. 次に決めること

1. この方向性（白と黒の面、細いセリフ体の英字、一文の中の写真の枠）で進めてよいか。
2. ロゴを作るか。試作では、Zodiak で「Advocates」と組んだ文字をロゴの代わりにしています。
3. 写真を、今の道具と場所の写真のまま公開するか、所属タレントの写真や撮影した写真に替えるか。
4. 公開先（GitHub Pages、Cloudflare Pages など）と、お問い合わせフォームの送信の仕組み。
5. 所属をご検討の方へ向けた情報（支援内容、所属までの流れ）を、別のページで載せるか。トップページの章は外しました。
